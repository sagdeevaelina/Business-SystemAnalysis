# Exercise 06 — Частоты и сроки передачи данных
---

## Подход

### Определения

- **Частота передачи** — как часто данные передаются по потоку. Может измеряться количеством событий в минуту/час/день.
- **Сроки доставки (latency)** — задержка между моментом инициации передачи и моментом, когда данные обработаны и подтверждены принимающей стороной.

### Параметры для каждого потока

1. Желаемая частота передачи
2. Желаемые сроки доставки (latency)
3. Максимально и минимально возможная частота
4. Максимально и минимально возможные сроки

## Детальные обоснования для каждого потока

### DF-01 — Заказ от ERP магазина

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Желаемая частота | event-driven | Заказ должен попасть в систему сразу при поступлении, иначе курьер не сможет его взять |
| Желаемая latency | ≤ 3 с | Оператор не должен ждать больше 3 с после нажатия «Сохранить» |
| Мин частота | 0/мин (ночь) | Допустимо отсутствие новых заказов |
| Макс частота | 200/мин | Запас от пика 100/мин; выше — нужен throttling |
| Мин latency | 0,5 с | Локальный INSERT в БД |
| Макс latency | 5 с | Граница, после которой — 503 Service Unavailable + retry |

---

### DF-02 — Свободные заказы курьеру

| Параметр | Push | REST pull | Обоснование |
|----------|------|-----------|-------------|
| Желаемая частота | event-driven | По действию курьера | Push — мгновенно; pull — при открытии экрана |
| Желаемая latency | ≤ 5 с | ≤ 3 с | Если push дольше 5 с — заказ могут забрать другие курьеры |
| Макс частота | 500/мин | 1 000/мин | Пиковые нагрузки в обед и ужин |
| Мин latency | 1 с | 0,5 с | При нормальной работе сети |
| Макс latency | 10 с | 5 с | Дольше — бесполезно (UI спиннер раздражает) |

---

### DF-03 — Статус от курьера

| Параметр | Online | Offline buffer | Обоснование |
|----------|--------|----------------|-------------|
| Желаемая частота | event-driven | Накопление | Каждое действие курьера должно быть зафиксировано |
| Желаемая latency | ≤ 1 с | ≤ 5 мин после восстановления | BSA12 sc 2.3 — статус должен отображаться у диспетчера мгновенно |
| Макс частота | 300/мин | — | Пик при массовой доставке |
| Мин latency | 0,3 с | — | При хорошей сети |
| Макс latency | 1 с | **1 ч** | BSA12 ex04 — offline support до 1 часа |

**Примечание:** offline buffer + idempotency означает, что курьер может изменить статус 100 раз без интернета, и при восстановлении всё доедет до сервера.

---

### DF-04 — Заказ → бухгалтерия (1С)

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Желаемая частота | event-driven (async) | Каждый заказ → одно сообщение в очередь |
| Желаемая latency | ≤ 15 мин | Бухгалтерии не нужно мгновенно; расчёты с поставщиками идут раз в месяц |
| Мин частота | 0/мин | Ночью заказов нет |
| Макс частота | 200/мин | Пик в обед/ужин |
| Мин latency | 1 с | Если 1С отвечает быстро |
| Макс latency | 24 ч | При недоступности 1С сообщения копятся в очереди; после 24 ч — DLQ + алерт |

---

### DF-05 — Доставка → бухгалтерия (1С: ЗУП)

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Желаемая частота | event-driven (async) | После завершения доставки |
| Желаемая latency | ≤ 15 мин | Расчёт зарплаты курьеров |
| Макс частота | 200/мин | Аналогично DF-04 |
| Макс latency | 24 ч | При недоступности 1С |

Аналогично DF-04.

---

### DF-06 — Оплата ← бухгалтерия (1С: ЗУП)

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Желаемая частота | Раз в час | Cron-pull; зарплата не требует real-time |
| Желаемая latency | ≤ 1 ч | С момента расчёта в 1С до отображения курьеру в личном кабинете |
| Мин частота | Раз в день | Если 1С временно недоступна |
| Макс частота | Раз в 5 мин | При большом числе расчётов в пиковый день |
| Мин latency | 1 мин | Если 1С поддерживает webhook |
| Макс latency | 24 ч | При длительном отказе 1С курьер видит вчерашние данные |

## SLA-сводка (договорные обязательства по latency)

| Поток | SLA latency (max) | Что нарушается при превышении |
|-------|-------------------|-------------------------------|
| DF-01 | 5 с | UX оператора, SLA с поставщиком |
| DF-02 | 10 с (push) | Курьер не успевает взять заказ |
| DF-03 | 1 ч (offline) | Диспетчер не видит реального статуса; неверный расчёт KPI |
| DF-04 | 24 ч | Запоздалая интеграция с бухгалтерией |
| DF-05 | 24 ч | Запоздалая зарплата курьера |
| DF-06 | 24 ч | Курьер видит вчерашние данные о зарплате |
