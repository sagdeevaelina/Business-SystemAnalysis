# Exercise 05 — Описание элементов запроса/ответа

## Интеграция №1 — Получение справочника каналов связи

| Параметр | Значение |
|----------|----------|
| **Вариант интеграции из UC** | Получение справочника каналов связи (шаги 2-5 основного сценария) |
| **Назначение интеграции по бизнесу** | Получение актуального списка каналов связи (SMS, Telegram, WhatsApp, VK, Email) для формирования выпадающего списка на UI при регистрации клиента |
| **Метод** | GET |
| **Направление передачи** | API Backend → UI |
| **Запрос или ответ** | Ответ |

### Элементы ответа (200 OK)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-получателя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|------------------------------------------|-------------|
| channelTypes | Список каналов связи | array | - | Да | Список каналов для выпадающего списка UI | Массив объектов ChannelType |
| channelTypes[].id | Идентификатор канала связи | integer | 9 | Да | Идентификатор справочной записи | Первичный ключ из таблицы LinkChannelTypes |
| channelTypes[].name | Наименование канала связи | string | 50 | Да | Отображаемое название в UI | Примеры: SMS, Telegram, WhatsApp, VK, Email |
| channelTypes[].code | Кодовое обозначение | string | 20 | Да | Технический код для бэкенда | Примеры: sms, telegram, whatsapp, vk, email |
| channelTypes[].isActive | Признак активности | boolean | - | Да | Определяет, показывать ли канал в UI | true — отображать, false — скрыть |
| channelTypes[].description | Описание канала связи | string | 255 | Нет | Подсказка для менеджера | Пример: "Уведомление через SMS" |

## Интеграция №2 — Проверка уникальности номера телефона

| Параметр | Значение |
|----------|----------|
| **Вариант интеграции из UC** | Проверка уникальности номера телефона (шаги 8-11 основного сценария) |
| **Назначение интеграции по бизнесу** | Проверка, не зарегистрирован ли уже клиент с указанным номером телефона, для предотвращения дублирования учётных записей |
| **Метод** | GET |
| **Направление передачи** | UI → API Backend |
| **Запрос или ответ** | Ответ |

### Элементы запроса (параметр в URL)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-отправителя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|-------------------------------------------|-------------|
| phone | Номер телефона | string | 11 | Да | Номер, введённый менеджером со слов клиента | Только цифры, 11 знаков (код страны + номер) |

### Элементы ответа (200 OK)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-получателя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|------------------------------------------|-------------|
| isRegistered | Признак регистрации | boolean | - | Да | Определяет дальнейшее действие менеджера | true — номер занят, false — свободен |
| message | Текст сообщения | string | 255 | Да | Сообщение для отображения менеджеру | Пример: "Номер телефона свободен" |

## Интеграция №3 — Создание новой записи клиента

| Параметр | Значение |
|----------|----------|
| **Вариант интеграции из UC** | Создание записи клиента (шаги 13-14 основного сценария) |
| **Назначение интеграции по бизнесу** | Сохранение данных нового клиента в системе: номера телефона, имени, предпочитаемого канала связи |
| **Метод** | POST |
| **Направление передачи** | UI → API Backend и обратно |
| **Запрос или ответ** | Запрос и ответ |

### Элементы запроса (тело запроса)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-отправителя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|-------------------------------------------|-------------|
| phone | Номер телефона | string | 11 | Да | Номер, введённый менеджером | Только цифры, уникальное значение |
| name | Имя клиента | string | 100 | Да | Имя, продиктованное клиентом по телефону | Только буквы, пробелы, дефис |
| channelTypeId | Идентификатор канала связи | integer | 9 | Да | Выбранный менеджером канал из справочника | Значение из справочника LinkChannelTypes |

### Элементы ответа (200 OK)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-получателя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|------------------------------------------|-------------|
| clientId | Идентификатор клиента | integer | 9 | Да | Уникальный ID для дальнейших операций | Первичный ключ из таблицы Clients |
| name | Имя клиента | string | 100 | Да | Подтверждение введённого имени | Дублируется из запроса |
| phone | Номер телефона | string | 11 | Да | Подтверждение введённого номера | Дублируется из запроса |
| channelTypeName | Наименование канала связи | string | 50 | Да | Подтверждение выбранного канала | Подтягивается из LinkChannelTypes по channelTypeId |
| login | Логин клиента | string | 50 | Да | Логин для входа в систему | Генерируется системой (phone или phone+имя) |
| tempPassword | Временный пароль | string | 8 | Да | Пароль для первого входа | Генерируется системой, отправляется клиенту |
| registrationDateTime | Дата и время регистрации | datetime | - | Да | Фиксация времени регистрации | Формат ISO 8601 |
| notificationSendStatus | Статус отправки уведомления | string | 20 | Да | Результат отправки пароля клиенту | Возможные значения: sent, failed, pending |

## Интеграция №4 — Отправка уведомления через сторонний сервис SMS

| Параметр | Значение |
|----------|----------|
| **Вариант интеграции из UC** | Отправка уведомления клиенту (шаги 17-19 основного сценария) |
| **Назначение интеграции по бизнесу** | Отправка клиенту SMS-сообщения с временным паролем и логином для входа в систему |
| **Метод** | POST |
| **Направление передачи** | API Backend → External Service SMS и обратно |
| **Запрос или ответ** | Запрос и ответ |

### Элементы запроса (тело запроса)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-отправителя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|-------------------------------------------|-------------|
| channelType | Тип канала отправки | string | 20 | Да | Фиксированное значение "sms" | Константа для данного вызова |
| phone | Номер телефона получателя | string | 11 | Да | Номер телефона клиента | Передаётся из данных регистрации |
| message | Текст сообщения | string | 160 | Да | Сформированное системой сообщение | Содержит логин и временный пароль |
| sendingTime | Время отправки | datetime | - | Да | Время инициализации отправки | Формат ISO 8601 |

### Элементы ответа (200 OK от внешнего сервиса)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Соответствие элементу системы-получателя | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|------------------------------------------|-------------|
| id | Идентификатор сообщения | string | 50 | Да | Уникальный ID сообщения в системе провайдера | Для логирования и отслеживания |
| status | Статус отправки | string | 20 | Да | Результат отправки | Возможные значения: sent, delivered, failed |
| sendingTime | Время фактической отправки | datetime | - | Да | Время, когда сервис отправил сообщение | Формат ISO 8601 |


> **Примечание:** В данном решении используется **унифицированная структура ошибок** для всех HTTP-кодов 4xx и 5xx. Это позволяет клиенту единообразно обрабатывать любые ошибки API.

### Унифицированная структура ошибки (для всех запросов)

| Идентификатор элемента | Название по бизнесу | Тип элемента | Размерность | Обязательность | Комментарии |
|------------------------|---------------------|--------------|-------------|----------------|-------------|
| errorCode | Технический код ошибки | string | 50 | Да | Уникальный идентификатор типа ошибки |
| message | Сообщение для пользователя | string | 255 | Да | Понятное описание ошибки для менеджера |
| timestamp | Время возникновения ошибки | datetime | - | Да | Формат ISO 8601 |
| details | Дополнительные детали | object | - | Нет | Содержит специфичную для ошибки информацию (например, название поля, рекомендуемое время ожидания) |

**Пример унифицированного ответа с ошибкой:**
```json
{
  "errorCode": "VALIDATION_FAILED",
  "message": "Поле name обязательно",
  "timestamp": "2026-05-20T14:30:00Z",
  "details": { "field": "name", "reason": "required" }
}
