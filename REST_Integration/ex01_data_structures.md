
# Структуры данных для UC02 и UC04

## UC02. Сформировать расписание мастера

**Участвующие сущности:**  
- `Сотрудник` (мастер)  
- `Роль сотрудника` (фильтр по роли «Мастер»)  
- `Окно` (слот времени)

### 1. Класс «Employee» (С)

| Атрибут | Тип данных | Длина | Обязательность | Ограничения / примечания |
|---------|------------|-------|----------------|--------------------------|
| employee_id | BIGINT | – | Да | PK, автоинкремент |
| person_id | BIGINT | – | Да | FK → `Персонал` (не показана, но подразумевается) |
| hire_date | DATE | – | Да | Дата найма |
| registration_date | TIMESTAMP | – | Да | Дата регистрации в системе |
| status | VARCHAR | 20 | Да | Значения: `active` / `blocked` |

### 2. Класс «Employee Role» (Роль сотрудника)

| Атрибут | Тип данных | Длина | Обязательность | Ограничения / примечания |
|---------|------------|-------|----------------|--------------------------|
| role_id | BIGINT | – | Да | PK |
| employee_id | BIGINT | – | Да | FK → `Сотрудник` |
| role | VARCHAR | 20 | Да | Значения: `Мастер`, `Менеджер`, `Админ` и т.п. |

### 3. Класс «Service Slot» (слот расписания)

| Атрибут | Тип данных | Длина | Обязательность | Ограничения / примечания |
|---------|------------|-------|----------------|--------------------------|
| slot_id | BIGINT | – | Да | PK |
| slot_date | DATE | – | Да | Дата слота |
| slot_time | TIME | – | Да | Время начала (длительность 1 час фиксирована) |
| employee_id | BIGINT | – | Да | FK → `Сотрудник` (мастер) |
| created_at | TIMESTAMP | – | Да | Время создания записи |
| updated_at | TIMESTAMP | – | Нет | Время последнего обновления |

## UC04. Зарегистрировать клиента (менеджер)

**Участвующие сущности:**  
- `Person` (физическое лицо)  
- `Client` (клиент, наследник Person)

### 1. Класс «Person» (из второй диаграммы)

| Атрибут | Тип данных | Длина | Обязательность | Ограничения / примечания |
|---------|------------|-------|----------------|--------------------------|
| id | BIGINT | – | Да | PK |
| login | VARCHAR | 50 | Да | Уникальный, обычно номер телефона |
| passwordHash | VARCHAR | 255 | Да | Хэш пароля (временный при регистрации) |
| fullName | VARCHAR | 100 | Да | ФИО клиента |
| registrationDate | DATETIME | – | Да | Дата регистрации |

### 2. Класс «Client» (наследует Person)

| Атрибут | Тип данных | Длина | Обязательность | Ограничения / примечания |
|---------|------------|-------|----------------|--------------------------|
| clientId | BIGINT | – | Да | PK (совпадает с person_id?) |
| personId | BIGINT | – | Да | FK → `Person` (связь 1:1) |
| registrationDate | DATETIME | – | Да | Дублирует поле из Person (возможно, избыточно) |
| totalVisits | INT | – | Да | Общее количество визитов |
| birthDate | DATE | – | Нет | Дата рождения |
| preferredMasterId | BIGINT | – | Нет | FK → `Employee` (предпочитаемый мастер) |

> **Примечание:** Номер телефона в use case передаётся через `login` класса `Person`. Временный пароль генерируется системой и сохраняется в `passwordHash` (временный хэш, который клиент меняет при первом входе).
