# UC04. Зарегистрировать клиента (менеджер)

**Контекст использования:** Менеджер, при общении с клиентом по телефону, регистрирует клиента, чтобы записать на обслуживание.

**Область действия:** барбершоп, оказание услуг клиентам.

**Уровень:** цель пользователя.

**Основное действующее лицо:** менеджер.

**Предусловия:** Клиент позвонил менеджеру. Менеджер зашел на сайт барбершопа.

## Основной сценарий

| № | Описание шага | Компоненты системы | Роль | Интеграция |
|:-|:--------------|:-------------------|:-----|:-----------|
| 1 | Менеджер открывает страницу регистрации клиента | UI | Менеджер | — |
| 2 | Менеджер вводит номер телефона и имя, которое клиент сообщил по телефону | UI | Менеджер | — |
| 3 | Клиентский интерфейс отправляет введенные данные на сервер | UI -> API Backend | Система | HTTP GET /api/client/check {params} |
| 4 | Сервер делает запрос к БД | API Backend -> DB Server | Система | SQL SELECT \| Справочник Clients |
| 5 | БД возвращает результат серверу | DB Server -> API Backend | Система | — |
| 6 | Сервер формирует ответ (телефон свободен) и передает клиентскому интерфейсу | API Backend -> UI | Система | — |
| 7 | Менеджер нажимает кнопку "Регистрация" | UI | Менеджер | — |
| 8 | Клиентский интерфейс отправляет данные клиента на сервер | UI -> API Backend | Система | HTTP POST |
| 9 | Сервер отправляет запрос на создание записи в БД в таблице Clients | API Backend -> DB Server | Система | SQL INSERT \| Справочник Clients |
| 10 | БД возвращает результат | DB Server -> API Backend | Система | — |
| 11 | Сервер генерирует временный пароль для клиента | API Backend | Система | — |
| 12 | Сервер формирует и отправляет на сторонний сервис сущность Уведомления, в том числе текст уведомления, включающий в себя временный пароль | API Backend -> External Service SMS | Система | REST API |
| 13 | Система отправки сообщений отправляет СМС клиенту | External Service SMS | Система | — |
| 14 | Система отправки возвращает результат отправки и время отправки в нашу систему | External Service SMS -> API Backend | Система | — |
| 15 | Сервер делает запись в журнале логирования | API Backend | Система | — |
| 16 | Сервер отправляет запрос на создание записи в таблице Notifications БД | API Backend -> DB Server | Система | SQL INSERT |
| 17 | Сервер отправляет в интерфейс пользователя сообщение об успешной регистрации | API Backend -> UI | Система | — |
| 18 | Менеджер получает уведомление об успешной регистрации клиента | UI | Менеджер | — |

> **Примечание:** предполагаем, что валидация данных происходит на стороне UI, невалидные или пустые данные не могут попасть на бэк.

## Альтернативный сценарий: ALT 3a — Сервис API Backend не доступен

| № | Описание шага | Компоненты системы | Роль | Интеграция |
|:-|:--------------|:-------------------|:-----|:-----------|
| 3a.1 | Клиентский интерфейс получает от бэкенда один из ответов недоступности сервиса | API Backend -> UI | Система | HTTP 503 Service Unavailable или HTTP 504 Gateway Timeout |
| 3a.2 | Клиентский интерфейс отображает менеджеру подробную информацию о возникшей ошибке | UI | Менеджер | — |

## Альтернативный сценарий: ALT 4a — В базе уже есть такой номер

| № | Описание шага | Компоненты системы | Роль | Интеграция |
|:-|:--------------|:-------------------|:-----|:-----------|
| 4a.1 | Сервер формирует ответ (телефон занят) и передает клиентскому интерфейсу | API Backend -> UI | Система | HTTP 200 OK + JSON |
| 4a.2 | Клиентский интерфейс показывает менеджеру плашку о том, что номер уже занят | UI | Менеджер | — |
| 4a.3 | Менеджер меняет номер телефона или завершает процесс регистрации | UI | Менеджер | — |

## Альтернативный сценарий: ALT 8a — У пользователя нет прав редактирования БД

| № | Описание шага | Компоненты системы | Роль | Интеграция |
|:-|:--------------|:-------------------|:-----|:-----------|
| 8a.1 | Сервер возвращает на клиентский интерфейс сообщение об отсутствии прав доступа и код ошибки | API Backend -> UI | Система | HTTP 403 Forbidden |
| 8a.2 | Клиентский интерфейс показывает менеджеру сообщение об отсутствии прав доступа и рекомендацией обратиться к администратору | UI | Менеджер | — |

## Альтернативный сценарий: ALT 12a — Сервис отправки СМС недоступен

| № | Описание шага | Компоненты системы | Роль | Интеграция |
|:-|:--------------|:-------------------|:-----|:-----------|
| 12a.1 | При вызове сервиса СМС произошла ошибка | API Backend -> External Service SMS | Система | REST API |
| 12a.2 | Система повторяет попытку до 3 раз с интервалом 30 секунд | API Backend | Система | — |
| 12a.3 | При 3 неудачных попытках система фиксирует ошибку в логах | API Backend | Система | — |
| 12a.4 | Сервер формирует ответ клиенту с пометкой, что сообщение не отправлено | API Backend -> UI | Система | HTTP 503 Service Unavailable |
| 12a.5 | Менеджер получает сообщение через интерфейс и сообщает клиенту данные по телефону или вручную | UI | Менеджер | — |

> **Примечание к UC:** В данном сценарии используется справочники Clients и EmployeeRoles, который содержатся в единственной БД, к которой обращается бекенд сервис, они не нуждаются в интеграции, так как БД входит в нашу систему. Внешний же справочник SMS-провайдеры является частью внешней системы, поэтому нуждается в интеграции с системой BRB.
